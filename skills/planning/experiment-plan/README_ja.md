# experiment-plan

[English](README.md)

機械学習の実験(モデルの学習や評価)について、ユーザーへのインタビューで実験計画を詰め、`templates/template_experiment_plan.md`をもとに`.mjun/experiments/YYYYMMDD_<slug>.md`へ保存する。目的、検証可能な仮説、判定基準を実験の実施前に確定し、実施後に結果と考察を追記できる計画書にする。

一般的な計画や設計には[`grill-me`](../grill-me/README_ja.md)または[`grill-self`](../grill-self/README_ja.md)を使う。計画の完了処理や結果の記入にも使わない。

## 使い方

- "機械学習の実験計画を作って"
- "評価実験を計画書にして"

## 動作

1. 会話の文脈とコードベースから、既知の情報を収集する。
2. 未決事項を一つずつ質問する。順序は目的、仮説(支持または反証を判定する数値基準を含む)、実験設計(モデル、データ、設定、ベースライン、評価指標、評価セット)、実装(必要な実装項目と既存資産で対応できる範囲)、スコープ(対象外、既知のリスク、関連する計画やIssue)。文脈から明らかな項目は省略する。
3. 質問と回答の対応を保ったまま決定事項をまとめ、ユーザーの承認を得る。
4. `.mjun/experiments/YYYYMMDD_<slug>.md`に計画書を保存する。ディレクトリがなければ作成し、日付には作成日を使い、連番は付けない。メタ表の`Status`は`planning`または`in-progress`で開始する。
5. `oxfmt .mjun/experiments/`でフォーマットし(`oxfmt`がなければスキップ)、ファイルパス、目的、仮説を報告する。commitはユーザーから依頼された場合だけ行う。

質問の規則: 質問は一度に一つで、各質問に推奨する選択肢とその理由を付け、`AskUserQuestion`などの選択ツールで行う。コードベースで確認できる事実は質問しない。必要な判断が揃ったらインタビューの終了を提案し、続行を求められた場合だけ続ける。

計画書の記述規則:

- 計画フェーズでは結果を記入しない。`## 実験結果`以降(仮説検証、考察、今後の展望)は見出しだけを残す。
- `## 実装`には実装項目だけを書く。詳細な手順、コマンド、コードスニペットはIssueやPRで扱い、メタ表と`## 実装`のIssue一覧からリンクする。
- 仮説は、実施後に「支持」「部分支持」「反証」「検証不可」のいずれかを判定できる粒度にし、合意した数値基準と比較対象を含める。
- `H1`、`Phase 2`、`Exp 1`などの識別子を別のセクション、ファイル、メタ表、目次から参照するときは、内容が分かる名称を併記する(例: 「H1: 弱教師強化」)。
- 目次は見出しと同期させる。

## 依存

- `oxfmt` (任意。整形に使う)

手順の詳細は[SKILL.md](SKILL.md)を参照。
