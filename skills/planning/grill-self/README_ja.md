# grill-self

[English](README.md)

計画や設計の意思決定のあらゆる分岐点を、agent自身の調査と自己問答で解消する。[`grill-me`](../grill-me/README_ja.md)と同じ設計ツリーを「幅」より「深さ」を優先して辿るが、ユーザーへの質問は一切行わない。各分岐点を根拠とともに自分で決定し、最後に意思決定ログを提示する。

ユーザーに質問して決めてほしい場合は[`grill-me`](../grill-me/README_ja.md)を使う。

## 使い方

- "自分で判断して計画を詰めて"
- "質問せずに設計を詰めて"
- "セルフgrillして"
- "grill-selfして"

## 動作

決定は必ず一度に一つずつ行い、複数の分岐をまとめて即断しない。各決定の前に、推測せずコードベース・既存の規約・ドキュメントの関連箇所を調べる。各分岐点は次の手順で解決する。

1. 論点: 何を決めるのかを一文で明示する。
2. 調査: 判断材料を集める。
3. 推奨案: 根拠とともに案を立てる。
4. 反論: 採択する前に、その案への反論(devil's advocate)を必ず一つ挙げて検討する。自己肯定的な決定に流れないためである。
5. 採択: 案を決定し、確信度をhigh / medium / lowで記録する。

調査では決められない価値判断(後方互換を切るか等)は、推奨案を仮採用して確信度lowとし、質問でブロックしない。論点を掘り尽くしたら終了する。

終了時の出力:

- 「論点 / 決定 / 根拠 / 確信度」の表(意思決定ログ)。
- 確信度lowの項目は「要確認」として表の後に再掲し、決定を覆した場合の影響範囲を一言添える。

ファイルは書き込まない。

手順の詳細は[SKILL.md](SKILL.md)を参照。
