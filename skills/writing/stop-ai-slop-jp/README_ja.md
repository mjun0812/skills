# stop-ai-slop-jp

[English](README.md)

AIで書いた日本語(ブログ、エッセイ、体験記、メモ、技術文書)を、人間が書いた自然で読みやすい文章に書き直す。AI臭の中心を記号や絵文字ではなく「書き手の不在」(立場、主体性、具体的な経験がないこと)として扱う。目標はAI臭を消すことと読みやすくすることの2つで、衝突したら読みやすさを優先する。人間らしさを演出として足すことはしない。

チェックは意味から表面へ進む。主体と立場、構造、文・段落、語彙・記号、可読性の順である。出力は採点レポートと番号付きの修正案である。新規執筆のための規範は持たないため、その場合は[`japanese-tech-writing`](../japanese-tech-writing/README_ja.md)または[`cognitive-rhythm-writing`](../cognitive-rhythm-writing/README_ja.md)を使う。

読者と文書の種類に合わせて校正する。技術文書では、対象・条件・操作・結果を明確にし、定着した専門用語や参照しやすい表を保つ。体験記の基準で感想や文体のムラを求めない。

## 使い方

- "AI臭を消して"
- "この文章を人間が書いたように直して"
- "AIっぽさを直して"

## 動作

1. 想定読者、文書の種類、既存の用語・表記を確認し、主体と立場、構造、文・段落、語彙・記号、可読性の順に問題を洗い出す。問題箇所は原文を引用して特定する。
2. 立場、主体性、具体性、リズム、簡潔さ、可読性の6軸を0〜10点で採点する(高いほど良い。合計0〜60)。
3. レポートを出力する。内容は判定(200文字以下の総評と修正の要否)、スコア表、重大な修正点、推奨する修正点で、番号は通し番号にする。重大な修正点が1件以上ある、またはいずれかの軸が6点以下なら修正は「必要」とする。
4. ユーザーが取り組む修正点を番号で指定する。指定された修正点だけを適用し、それ以外は変更しない。
5. 原文と照合し、曖昧な語の取り残しと仕様の欠落がないか確認する。用語を変更したら、承認された編集範囲の見出し・本文・表・図・リンク表示・sidebarで意味と表記を揃える。コードの識別子や実際のUIラベルは保持し、範囲外の修正が必要なら報告する。

重大と推奨は「理解を妨げるか」で振り分ける。主体と立場・構造の問題、単独の否定文の多発、読み手の反応を先取りするラベル、指示語で対象を追えない問題は重大である。語彙・記号の問題や軽微な構造上の蛇足は推奨である。

安全規則: 修正案が新しい事実(行為者、数値、固有名詞、エピソード)を必要とするときは、推測で補わない。「要確認: この方針は誰が決めたか」のように書き手への質問の形で出す。書き手が具体的な話を持っていない場合、校正側が作って埋めることはしない。

技術文書では、曖昧な平易化や擬人化、将来の対応を暗示する不要な時間表現も見直す。referenceの見出しは対象と内容を示す名詞句を基本とし、読者に不要な初歩説明やコマンドの既定値指定を省く。特殊な条件の対処は基本手順から分け、必要な前提条件や注意は残す。textlintなどの結果は見直しの手がかりであり、警告の有無だけで自然さを判定しない。

パターンのカタログは`references/structures.md` (避けるべき構造6系統)と`references/phrases.md` (撲滅すべき語彙9系統)である。その時々のモデルの癖を集めたもので、網羅でも恒久でもない。リストにない兆候でも、書き手の不在や理解の妨げに結びつくなら指摘する。
