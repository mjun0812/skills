# cognitive-rhythm-writing

[English](README.md)

日本語の説明的な文章に緩急を設計するための規範。規範を定めるskillで、引数を取らず、単体ではファイルを出力しない。agentが文章を書く、または診断するときに読み込み、その規則に従う。

緩急を装飾ではなく、読者の認知モードの切替(観察→逡巡→断定→再観察)と未回収の緊張の管理として扱う。密度の高い文章が退屈になるのは情報が多いからではなく、全文が同じ認知モードで書かれているからである。

調べ物ではなく読み物として通読させたい文章で、日本語の文章の基準である[`japanese-tech-writing`](../japanese-tech-writing/README_ja.md)に重ねて使う。既にある文章のAI臭を消すには[`stop-ai-slop-jp`](../stop-ai-slop-jp/README_ja.md)を使う。

## 使い方

読み物として読ませたい章・記事・解説文を生成するとき、または「密度はあるが平坦でおもしろくない」文章を診断・修正するときに使う(SKILL.mdのdescriptionは「日本語で説明を行う時に使用するskill」)。決まったトリガー文言はない。

## 動作

次を扱う。

- 文の拍: 短文で足場を打ち、長めの文で流し、短文で止める。断定と逡巡を交互に置く。
- 段落の密度波形: 密な段落が2〜3個続いたら疎の段落を置く。具体に寄る段落と意味づけで一段引く段落を交互にする。
- 冒頭の設計と、予告せずに節へ入る方法。
- 列挙の着地、問いの回収と結び。
- 緩みと駄文の見分け方。
- 執筆後の機械的な点検手順: 話題テスト、漏出テスト、緊張台帳、拍の点検、境界の点検。
- 平坦な文章を診断するための、症状から処方を引く対応表。

特に重要な制約は2つある。

- リズムの材料は対象そのもの(出来事、データ、発言、語り手の判断状態)からだけ取る。材料がない位置には何も足さず、平坦なまま残す。本文の進行を語る文(「次は〜」)は駄文として扱う。
- 装置は宣言せず、内容として実現する。この規範の語彙や例文を本文にそのまま書かない。

拍を作るために必要な文脈共有まで削って短くすることは禁止する。
