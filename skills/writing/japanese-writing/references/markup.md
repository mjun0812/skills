# 表、箇条書き、図の使い分け

出力先が表、箇条書き、図を描画するとき(Markdown、HTMLなど)に、内容をどの形で書くかを決める規範。
形は内容の形から選ぶ。見た目を整えるために選ばない。

## 出力先を確かめる

書く前に、出力先がどの記法を描画するかを確かめる。

| 出力先                                                             | 使える形                                                  |
| ------------------------------------------------------------------ | --------------------------------------------------------- |
| GitHubのMarkdown(README、Issue、PR)                                | 表、箇条書き、番号付きリスト、コードブロック、Mermaidの図 |
| そのほかのMarkdown                                                 | 表、箇条書き、番号付きリスト、コードブロック              |
| HTML                                                               | `table`、`ol`、`ul`、`pre`、`figure`                      |
| 記法を描画しない出力先(メール、commitメッセージ、プレーンテキスト) | 文と改行だけ                                              |

- Mermaidは、出力先が描画すると確かめられたときだけ使う。確かめられなければ、表か番号付きリストで書く。
- 既存の文書に書き足すときは、その文書が使っている記法に合わせる。
- 記法を描画しない出力先では、`|` や `-` で表や箇条書きの形を作らない。並べる項目は文で書き、手順は「1.」「2.」と行を分けて書く。
- HTMLでは、見た目を作るために `table` や `br` を使わない。

## 内容の形から選ぶ

| 内容の形                                                               | 書き方                         |
| ---------------------------------------------------------------------- | ------------------------------ |
| 主張と根拠、因果、経緯、判断の理由                                     | 散文                           |
| 順序のある操作                                                         | 番号付きリスト                 |
| 順序のない同種の項目が3つ以上                                          | 箇条書き                       |
| 複数の対象を、2つ以上の同じ観点で比べる                                | 表                             |
| 名前と値の対応、用語と定義の対応                                       | 表、またはラベル付きの箇条書き |
| 分岐や戻りのある流れ、状態遷移、複数の登場者のやりとり、構成要素の関係 | 図                             |
| コマンド、コード、設定、ログ                                           | コードブロック                 |
| 既存のファイル構成やコードへの小さな変更                               | `diff` のコードブロック        |

1つの節に形の違う内容が入っているときは、内容ごとに形を分ける。

## 散文のままにする内容

- 論証を箇条書きにしない。項目の頭に接続表現(「だから」「しかし」「その結果」)が付く箇条書きは、項目どうしが因果でつながっている。接続表現を残して段落に書く。
- 項目が2つ以下なら、箇条書きにせず文で書く。
- 比べる観点が1つしかない内容は、表にせず箇条書きか文で書く。
- 一方向に進むだけの手順は、図にせず番号付きリストで書く。
- 本文の言い換えにしかならない図は入れない。

## 箇条書きと番号付きリスト

- 直前に、何を並べるのかを1文で書く。
- 項目の文法の形を揃える。名詞句で始めたら全項目を名詞句にし、文で始めたら全項目を文にする。
- 入れ子は2段までにする。
- 1つの項目に2文より多く必要なら、箇条書きをやめる。小見出しと段落にするか、表にする。
- 番号付きリストは、1項目に1つの操作を書く。操作の結果や注意は、その項目の下に字下げして書く。
- 番号が順序を示すので、項目の頭に「まず」「次に」「最後に」を書かない。

## 表

- 行に比べる対象を、列に観点を置く。
- 直前に、比べる対象と観点を1文で書く。
- 列は5つまでにする。超えるなら、観点のまとまりごとに表を分ける。
- セルには語句か1文を書く。2文以上になる内容は、表の外に段落で書く。
- 単位は列の見出しに書き、セルには数値だけを書く。
- 該当しないセルは空にせず、「なし」「対象外」と書く。
- 一部の対象にしか当てはまらない事実は、列にしない。表の外に文で書く。ほかの対象のセルを埋めるために、事実を作ることになるためである。

## 図

- 1つの図には1つの論点だけを描く。ノードが15個を超えるなら、論点ごとに図を分ける。
- 図の種類は、描く内容で選ぶ。

| 描く内容                       | Mermaidの記法     |
| ------------------------------ | ----------------- |
| 構成要素の関係、分岐のある処理 | `flowchart TD`    |
| 複数の登場者のやりとり         | `sequenceDiagram` |
| 状態遷移                       | `stateDiagram-v2` |
| テーブルどうしの関係           | `erDiagram`       |

- 図の直前に、その図が何を示すかを1文で書く。
- 図の説明には、図に描いたものを書く。図に描かなかったものを挙げない。
- ノードのラベルには、本文と同じ用語を使う。
- 図に描いた条件と数値(回数、時間、閾値)は、本文にも書く。図の中の文字は検索できないためである。
- Mermaidでは色を指定しない。読み手の画面の配色で描画されるので、固定した色は読めなくなることがある。

## 見出し、強調、区切り

- 見出しと本文に、装飾の絵文字を付けない。
- 対比を `❌` と `✅` の行で書かない。表か地の文で書く。
- 区切り線(`---`)を節の区切りに使わない。節は見出しで区切る。
- 太字と箇条書きのラベルの規則は、SKILL.mdの「整形」に従う。

## 文書の種類ごとの使い方

| 種類      | 表と箇条書き                                         | 図                                           |
| --------- | ---------------------------------------------------- | -------------------------------------------- |
| reference | 仕様、比較、手順のように、読者が引いて使う内容に使う | 構成、状態遷移、やりとりを示すときに使う     |
| 解説      | 比較と手順に使う。論証は散文で書く                   | 本文だけでは追いにくい仕組みを示すときに使う |
| 体験記    | 散文を基本とする。手順や一覧を載せる箇所にだけ使う   | 仕組みを説明する箇所にだけ使う               |

## 修正での扱い

- 形が内容に合っていない箇所は、形を変える。散文に埋もれた比較は表に、箇条書きにされた論証は段落に、1文に詰まった手順は番号付きリストにする。
- 内容に合っている表と箇条書きは、そのまま残す。
- 形を変えても情報を落とさない。表や図に入らない事実は、その外に文で書く。
- 形を変えた箇所は「変更点」に挙げる。
