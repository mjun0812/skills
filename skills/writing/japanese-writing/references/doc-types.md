# 文書の細かい種類ごとの扱い

文書が次の13種類のどれかに当たるときに読む。
種類ごとに、その文書でふつうの書き方と、それでも直すものを定める。
「残す書き方」に挙げたものは、ほかの規範が直すとしていても、その種類では直さない。

## 種類を決める

| 種類               | SKILL.mdの種類 | 依頼の手がかり                 | 本文の手がかり                                         |
| ------------------ | -------------- | ------------------------------ | ------------------------------------------------------ |
| PR説明             | reference      | PR、変更の説明                 | 概要、変更点、テストの見出し。Issueの番号、ファイル名  |
| 障害報告           | reference      | 障害、インシデント、ふりかえり | 発生日時、影響範囲、原因、暫定対応。時刻つきの経過     |
| 手順書             | reference      | 手順書、マニュアル、使い方     | 番号つきの手順、「〜してください」の連続、注意の欄     |
| 議事録             | reference      | 議事録、会議のメモ             | 日時、出席者、議題、決定事項の欄                       |
| 提案書             | reference      | 提案、企画、稟議               | 背景、目的、費用、期待する効果。判断を求める文         |
| 規程、仕様書       | reference      | 規程、契約書、公用文、仕様書   | 条の番号、「〜するものとする」、定義の条               |
| メール、チャット   | reference      | メール、チャット、返信         | 宛名、挨拶、署名、結びの言葉                           |
| スライド           | reference      | スライド、発表資料             | ページの区切り、ページごとの短い見出しと箇条書き       |
| 技術記事           | 解説           | 技術ブログ、記事               | 導入の段落、コードの囲みとその説明                     |
| 論文、研究レポート | 解説           | 論文、予稿、調査報告           | 「本研究では」、引用の書き方、「考察」「結論」の見出し |
| エッセイ、小説     | 体験記         | エッセイ、日記、小説           | 一人称の語り、体験と気持ち、会話文と地の文             |
| 紹介記事、宣伝文   | 体験記         | 紹介記事、おすすめ記事         | 「〇選」「おすすめ」の見出し、価格や購入先の案内       |
| 台詞、脚本         | 体験記         | シナリオ、脚本、台本           | `名前「…」` の行、場面の番号、ト書き                   |

- 依頼の行き先か宛先が1つの種類を示すときは、その種類と決める。本文に1つの種類の手がかりが2つ以上あるときも同じである。
- 依頼の指定と本文の形が食い違うときは、指定に従う。本文を指定された種類の形に組み替えない。
- どれにも当たらない文書は、種類を決めずにSKILL.mdの3種類だけで扱う。
- 商品や店を勧める記事は、個人のブログへ載せるものでも紹介記事として扱う。

## 全種類に共通する扱い

- 見出し、節、項目、手順、ページ、条文の数と順を変えない。本文をすべて削ることになった節も、見出しを残して「要確認」に挙げる。
- 数値、単位、期日、金額、固有名詞、URLと、それが掛かる範囲を変えない。
- その種類の形に合わせるために、構成を組み替えない。結論を前に出す直しもしない。ただし、提案書、技術記事、論文、障害報告の原因と対策の節は、[paragraph.md](paragraph.md) の「修正での扱い」に従って組み替える。
- 絵文字(メール、チャット、紹介記事を除く)、チャット応答の名残、本文に残ったAIへの指示は、どの種類でも直す。

## PR説明

| 残す書き方                                                   | それでも直すもの                                                                 |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| 変更点と確認したことの箇条書き、チェックリスト               | 変更報告の述語の抜け                                                             |
| 体言止めの項目(「期限切れのキャッシュを削除する処理を追加」) | 実施済みと予定の取り違え                                                         |
| テンプレートの見出し(概要、変更点、テスト)                   | 確認したことと確認していないことを混ぜた文                                       |
| 識別子が主語の文                                             | ラベルとコロンで説明の文を並べただけの箇条書き(「**改善点**: 〜を改善しました」) |

- 1つの箇条に1つの変更を保つ。箇条書きを地の文にまとめない。
- 体言止めの項目を文にのばさない。
- テンプレートの見出しは、本文をすべて削ることになっても残す。本文には何も書き足さず、その節を「要確認」に挙げる。

## 障害報告

| 残す書き方                                               | それでも直すもの                               |
| -------------------------------------------------------- | ---------------------------------------------- |
| 時刻と事象の箇条書きや表、体言止めの経過(「10:05 復旧」) | 調査中の原因を言い切る書き方                   |
| 「発生」「復旧」「影響範囲」「暫定対応」のような報告の語 | 伝聞を言い切りに変える書き方                   |
| 伝聞の「〜とのこと」、原因が調査中であることを述べる文   | 見聞きした時刻と、出来事が起きた時刻の取り違え |
| 再発防止の決意を述べる結び                               | 結びの大げさな語(「全社一丸となって」)         |

- 時系列の順を変えない。

## 手順書

| 残す書き方                                                     | それでも直すもの                                               |
| -------------------------------------------------------------- | -------------------------------------------------------------- |
| 番号つきの手順と、1手順1動作                                   | 条件がどの手順に掛かるかのずれ                                 |
| 「〜してください」の連続、注意や警告の欄                       | 警告や必須の指示を弱める書き方                                 |
| かぎ括弧の画面の項目名(「保存」ボタン)                         | 先に済ませる作業を括弧に入れた文。括弧から出して行う順に並べる |
| 扱う範囲を示す文(「この手順書では、退職の手続きは扱いません」) |                                                                |

- 条件が1つの動作だけに掛かる手順(「設定を確認し、問題がなければ再起動してください」)は、2つに分けない。

## 議事録

| 残す書き方                           | それでも直すもの                                     |
| ------------------------------------ | ---------------------------------------------------- |
| 項目に分けた構造、体言止めの項目     | 発言者、作業した人、担当を引き受けた人の取り違え     |
| ラベルと値(「**日時**: 10月1日」)    | 元にない決定やToDoの記載                             |
| 同じ文末の連続、伝聞の「〜とのこと」 | 担当が書かれていないことを「担当未定」と決める書き方 |

- 話題の順と見出しを変えない。原文の「未定」も残す。

## 提案書

| 残す書き方                         | それでも直すもの                                               |
| ---------------------------------- | -------------------------------------------------------------- |
| 結論や提案を先に置いた構成         | 効果の見込みを強める書き方(「見込みです」を「なります」にする) |
| 論点や費用の箇条書き               | 元にない効果を足す書き方                                       |
| 判断を求める文(「ご判断ください」) | 依頼、相談、提案、決定の取り違え                               |

## 規程、仕様書

| 残す書き方                                                 | それでも直すもの                                                      |
| ---------------------------------------------------------- | --------------------------------------------------------------------- |
| 正式な漢語と定義された語(「実施する」「届出」「甲」「乙」) | 根拠のない誇張(「飛躍的」「画期的」)                                  |
| 義務、権限、許可、努力の語と、「〜するものとする」の文末   | 意味のぼやけた流行語                                                  |
| 条文の形、定義の条、ただし書き、長い条件の文               | 条件や例外の掛かる先が読み取りにくい文(掛かる先が1つに決まるときだけ) |
| 名詞化の言い回し(「〜に関して」「〜を実施」)               |                                                                       |

- 許可(「してよい」)、権限(「できる」)、説明(「する」)、保証(「必ず〜する」)は仕様の違いなので、互いに替えない。
- 条文を分けたりつないだりしない。

## メール、チャット

| 残す書き方                                                             | それでも直すもの                                                   |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 宛名、挨拶(「お世話になっております」)、結び、署名                     | 誤字、脱字、敬語の誤り                                             |
| 敬語の度合い(「〜いただけますでしょうか」を「〜してください」にしない) | 二重敬語(「ご確認させていただきました」→「確認いたしました」)      |
| クッション言葉(「お手数ですが」「恐れ入りますが」)                     | 何を頼んでいるのかが分からない文                                   |
| チャットの口語(「〜かも」「〜しときます」)                             | 1文に頼みごとが2つ以上あり、どちらに返事をすればよいか分からない文 |
| 書き手が気持ちを表すために使った絵文字と「！」                         | 同じ詫びや礼が3回以上並ぶ箇所(2回まで残す)                         |

- 相手への実際の問いや勧め(「いかがでしたでしょうか」「ぜひお試しください」)は、定型の結びとして削らない。
- 頼みごと、期限、日時、金額、宛名を変えない。期限を「中旬」のようにぼかさない。
- 挨拶やクッション言葉を削って、用件だけにしない。
- 敬語を上げるのは、依頼で書き手と読み手の関係(上司、取引先)を示されたときだけにする。
- 期限がどちらの頼みごとに掛かるか決まらない文は、書き換えずに「要確認」に挙げる。

## スライド

| 残す書き方                                     | それでも直すもの                                         |
| ---------------------------------------------- | -------------------------------------------------------- |
| 短い句や体言止めの見出しと箇条書き、ラベルと値 | 長い文の見出し。何を扱うページかが分かる短い項目名にする |
| 目次、「ポイントは3つです」、まとめのページ    | 縮めすぎた標語の見出し(「速さは、信頼。」)               |
| ページの区切り(`---`)、話者のノート            | 評価の語だけを並べる型(「速い。軽い。安い。」)           |
|                                                | 見出しと1行の箇条にある、間を作るだけの読点              |

- 1つの箇条は1行に収まる長さを保つ。体言止めと助詞の省略を残し、文にのばさない。
- 説明の文をページに足さない。
- 条件(「急ぎなら、」)、逆接、理由、短い時の句(「その夜、」)の読点は残す。

## 技術記事

| 残す書き方                             | それでも直すもの                                             |
| -------------------------------------- | ------------------------------------------------------------ |
| コードの囲みとその説明、項目名の見出し | 続く内容を予告するだけの導入(「本記事では〜をご紹介します」) |
| 並列が明確な手順の箇条書き             | 本文を繰り返すだけの「まとめ」の見出しと段落                 |
| 原文の常体か敬体                       | 「本稿では」「筆者は」のような論文調                         |
| 対象読者、前提、参照先を示す文         | 冒頭の中身のない前置き(「近年、AI技術の発展は目覚ましく」)   |

- 検証の記事にある「仮説ではX、実際はY」の対比は残す。
- コードの囲みの中、コマンド、識別子を変えない。
- 1文に単位つきの数値が4つ以上あるときは、表か箇条書きに分けるかを確かめる。分けるときも数値を消さず、丸めず、何と何を比べた値かを残す。

## 論文、研究レポート

| 残す書き方                                                               | それでも直すもの                                      |
| ------------------------------------------------------------------------ | ----------------------------------------------------- |
| 慎重な言い方(「と考えられる」「可能性がある」「示唆する」「の範囲では」) | 係り先が分からない文、主語と述語がかみ合わない文      |
| 引用の書き方、数値、単位、統計の値                                       | 「の」が4つ以上続く箇所                               |
| 専門用語、「である」調                                                   | 同じ文末が3文以上続く箇所(語順や文のまとめ方で整える) |
| 「本研究では」「先行研究」、「考察」「結論」の見出し                     | データや出典に基づかない誇張                          |
| 条件と結果が1文にまとまった長い文                                        |                                                       |

- 慎重な言い方を言い切りに変えない。言い切りを弱めることもしない。
- 引用の番号や括弧を、別の文や句へ動かさない。どの主張を支える引用かが変わるためである。
- 読み手が一般の人だと指定されても、専門用語を言い換えない。

## エッセイ、小説

| 残す書き方                                       | それでも直すもの                                     |
| ------------------------------------------------ | ---------------------------------------------------- |
| 書き手の語り、話し言葉、気持ちの語、体験の順     | 主語と述語を取り出すと成り立たず、連想もできない比喩 |
| 何を何に例えたかが読み取れる比喩                 | 係り方がずれて、文として通らないもの                 |
| 小説の会話、短い文の連続、ダッシュ、三点リーダー | エッセイの比喩の動詞(「じわじわ効いてきた」)         |
| 書き手が残した複数の読み                         | 否定と肯定を2文に分けた対比(小説の語りと会話は除く)  |

- 書き手の文のリズムを残す。文の長さを揃えない。
- 一人称と体験を足さない。
- あとの文で例えた理由を説明している比喩は残す。
- 比喩を直すときは、前後の文から分かる様子だけで書く。分からなければ「要確認」に挙げる。

## 紹介記事、宣伝文

| 残す書き方                                                               | それでも直すもの                                                                                       |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| 「！」(同じ段落に3つ以上あっても減らさない)                              | 誤字、脱字                                                                                             |
| 見出しのキャッチコピー、「〇選」「おすすめ」の見出し                     | 主語と述語がかみ合わない文                                                                             |
| 評価の語を短く重ねる型(「安い。うまい。早い。」)                         | 事実のように書かれた根拠のない誇張(「県内でいちばん売れている」)。書き換えずに「要確認」で根拠を尋ねる |
| 勢いのある語(「最強」「イチオシ」「抜群」)、強める語(「本当に」「ぜひ」) |                                                                                                        |
| 同じ褒め言葉の繰り返し、書き手が使った絵文字                             |                                                                                                        |

- 書き手の勢いが記事の魅力なので、落ち着いた言い方に置き換えない。
- 元にない褒め言葉を足さない。
- 一覧の項目の数と順、価格、商品名、店名、購入先を変えない。

## 台詞、脚本

| 残す書き方                                       | それでも直すもの                                             |
| ------------------------------------------------ | ------------------------------------------------------------ |
| 台詞の口調、方言、言いよどみ、語尾の「！」「？」 | 台詞の最後の「。」(ほとんどの台詞が「。」で終わっているとき) |
| 台詞の中の短い文の連続、主語を書かない言い方     | 台詞の外の誤字と脱字                                         |
| ト書きと地の文の短い文、体言止め                 | 誰が何をするかが読めないト書き                               |

- 台詞の数と順、話し手の名前、場面の区切りを変えない。
- 台詞の言い回しを、地の文の規則(主語を補う、文の長さ、比喩)で直さない。
- 依頼か本文で句点を打つ書き方を指定されているときは、台詞の最後の「。」を外さない。
