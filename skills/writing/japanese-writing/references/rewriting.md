# 書き直しの規則

既にある文章を直すときに、どこを直し、どこを残すかを決める規則。
語の形ではなく、その文が担っている働きで判断する。

## 読み手として読む

型を探す前に、原文を上から1回、初めて読む読み手として読む。
読み手が止まる箇所を書き出し、そこを直す候補にする。

- 前に戻らないと、誰が何をするのか、何を指すのかが分からない箇所
- 動作をする人が文の中にいるのに、受け身で書いた箇所(「担当者から案が示された」)
- 助詞を落として名詞を詰めた箇所(「書類不備発見時は」)
- 修飾や条件の掛かり先を読み違える箇所
- 同じ語や言い回しが近くで続く箇所

直したあとも、修正後の文章を読み手として上から通読し、用件と、誰が何をするかが伝わることを確かめる。
読み手にとって何が読みやすくなったかを言えない書き直しは採らない。

## 文の種類を保つ

直す前に、各文の種類を確かめる。直したあとに、種類が変わっていないことを確かめる。

| 文の種類     | 変えてはならない方向               |
| ------------ | ---------------------------------- |
| 事実         | 意見や予定にしない                 |
| 意見、評価   | 事実の言い切りや、目標の文にしない |
| 依頼、決まり | 説明の文にしない                   |
| 例え、比喩   | 言い切りにしない                   |
| 皮肉、反語   | 疑問文や字義どおりの文にしない     |
| 仮定、予測   | 予定や事実にしない                 |
| 引用、伝聞   | 書き手の言い切りにしない           |

- 文を分けたりつないだりしても、元の種類をどこかで保つ。
- 書き手がわざと複数の読みを残した箇所は、1つの読みに決めない。
- 決意や抱負を述べる結び(「〜に取り組んでまいります」)は、内容を残して大げさな語だけを直す。

## 文書の立場と文末

文末を直す前に、誰が、誰に、何のために書いた文書かを確かめる。立場は次の3つである。

| 立場   | 該当する文書                       | 動く人 |
| ------ | ---------------------------------- | ------ |
| 勧め   | 読み手に勧める、頼む文書           | 読み手 |
| 決まり | 運用ルール、手順書、お知らせ、仕様 | 読み手 |
| 説明   | 技術の説明、報告、体験             | いない |

- 立場は、依頼の行き先と読み手、次に本文の手がかり(主語、宛名、署名、見出し)で決める。分野の名前だけでは決めない。
- 文末を直すのは、動作主、時制、働きが意図とずれて読めるときと、常体と敬体が入り交じるときである。
- 実施済みの変更、現在の動作や方針、今後の予定を、時制で書き分ける。完了した変更を予定の「〜します」にしない。
- システムの動作(「返します」)、機能(「できます」)、依頼、予定は、それぞれの形を保つ。
- 同じ文末が続くことは、見直すきっかけにとどめる。語尾を散らすために、文の働きや時制を変えない。
- 敬体にすることと、すべての動作を「〜します」にすることは別である。

## 主語と目的語を補う

- 「誰が、何を、どうした」は、原文、依頼、資料に書いてある語だけで補う。元にない担当者や動作主を作らない。
- システムの動作を、人の行為に変えない。
- 指示語を名詞に戻すのは、指す先が1つに決まるときだけにする。近くにある名詞というだけで選ばない。
- 2通りに読める箇所は、1つに決めず「要確認」に挙げる。
- 動作主が切り替わる箇所では、主体を書く。
- 書き手の一人称(「私は」)を足すのは、依頼で書き手を示されたときだけにする。

## つなぎ言葉と予告

- つなぎ言葉、主題の「も」、文頭の指示語は、何と何をつなぐかを確かめる。根拠が前後にあれば正しい語に直し、なければ「要確認」に挙げる。
- 予告だけの文は、続く中身の文と1文にまとめる。本文と重なるだけなら削る。
- 数の予告(「重要なポイントは3つです」)は、数と項目が合うときだけ、続く中身とまとめる。合わないときは、数と項目を原文のままにして「要確認」に挙げる。
- 対象読者、前提、扱う範囲、参照先を示す文は、予告ではなく案内なので残す(「この記事は、Gitの基本操作を知っている人を対象にしている」)。
- 「これにより」は、前の文から後ろの結果が生じると読み取れるなら残す。因果を読み取れないまま機械的につないでいるときだけ直す。

## 否定の対比を確かめる

「AではなくB」は、Aを消してBだけを言う文を作り、原文と主張が同じかを見て決める。

Aが次のどれかを正しているなら、主張が変わるので残す。

| Aが正しているもの          | 例                                                                     |
| -------------------------- | ---------------------------------------------------------------------- |
| 読み手が思い込みやすい原因 | 遅かったのはデータベースではなく社内のネットワークだった               |
| 検証で外れた仮説           | 最初はメモリ不足だと考えたが、実際は開けるファイル数の上限に達していた |
| 読み違えやすい数や語の意味 | この表の数字は売上ではなく受注の件数である                             |
| 誤解されやすい効果         | 速くなったのではなく、待ち時間の表示を変えただけである                 |
| 相手の受け取り方           | 責めるつもりはなく、経緯を知りたいだけである                           |

読み手が持たない見立てを立てて打ち消しているだけなら、Aを消して「Bだ」と書く。

| 原文                                           | 直した文                         |
| ---------------------------------------------- | -------------------------------- |
| 必要なのは魔法ではなく、毎朝の確認の手順である | 必要なのは毎朝の確認の手順である |
| これは戦略ではなく、戦術でもなく、習慣である   | これは習慣である                 |

- 否定と肯定を2文に分けた対比(「Aではない。Bだ。」)でAを残すときは、1文にまとめる。「なく」のあとに読点を足さない。
- 後ろの文が否定の根拠を足しているとき(「回線のせいではない。ほかの部署でも同じ時間に遅れていた」)は、1文にまとめない。
- 直したあと、否定していたAが肯定の側に移っていないかを確かめる。「AとBを優先した」「Aに加えてB」「まずAを」のようにAが目的や優先の側に出ていたら、主張が逆になっている。

## 比喩と擬人化

- 比喩の動詞は、何がどう変わったかを書く。効き目だけをぼんやり言う形(「助けになっている」)にしない。
- 原文より強い確度の語(「確実に」「必ず」)を足さない。
- 「骨が折れる」のような慣用句は残す。
- 物や概念に感情や意志を持たせた擬人化(「コードが語る」)は直す。
- 働きを客観的に述べる文(「このツールはログを集める」)と、働きが一読で分かる擬人化(「センサーが異常に気づく」)は残す。
- 設計の用語(「責務を持つ」「依存する」)は残す。
- コードを人の知識や役目にたとえた言い方(「呼び出し元の事情を知っている」)は、実際の動作が資料に書いてあるときだけ、何を受け取り、何を返すかの文に直す。分からなければ「要確認」に挙げる。
- 体験記では、何を何に例えたかが読み取れる比喩を残す。主語と述語を取り出すと成り立たず、連想もできない比喩(「午後が膝を抱える」)は直す。

## 漢語と和語

- 助詞を落として漢語を詰めた句は、語を残して助詞と動詞を補う(「書類不備発見時は」→「書類の不備を見つけたときは」)。定着した複合語(「ログイン画面」)は詰まりとして扱わない。
- 書き直した箇所に、原文にない名詞化の言い回しを足さない(「〜の実施」「〜を行う」「〜を担保」「〜を図る」「〜に資する」「〜が可能です」「〜の観点から」)。
- 中身のない硬い漢語は、ふだんの言葉にする(「活用する」→「使う」、「テストを実施する」→「テストする」)。
- 和語の動詞に替えるのは、目的語が文の中で追え、意味の幅が同じときだけにする。
- 漢字の割合を下げるためだけに、語を替えない。

## 文を削るとき

- 文や語句を削る前に、削る部分にしかない主張、条件、数値、期限がないかを確かめる。あれば、同じ意味で本文に残す。
- 名詞がもともと持つ評価を述語で言い直すだけの文(「書き心地がなめらかである」)は、前後に評価の中身(素材、寸法、数値)があれば、その事実の文に寄せて1文にする。
- 「〜と言っても過言ではない」は、誇張の枠を外して事実をそのまま書く。数値の裏付けがある強調は残す。
- 公開する文に残った仮の文字(「〇〇」「XXX」「[ここに〜を入れる]」)は、入れる値が原文と資料に書いてあるときだけ置き換える。分からなければ「要確認」に挙げる。
- 書き手がAIに出した指示が本文に残った文(「今回は一般論ではなく〜に絞って紹介する」「〜なトーンで振り返る」)は削る。
