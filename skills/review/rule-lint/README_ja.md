# rule-lint

[English](README.md)

`CLAUDE.md`・steering・ADR・レビュー指摘などに文章で書かれたコード規約を、linter設定・ast-grep・scriptによる機械的なチェックへ変換する。
チェックを作るだけでなく、テストで動作を確かめ、git hookとCIへ接続するまでを1単位とする。

## 使い方

- 「規約をlintにして」
- 「ルールを機械的にチェックできるようにして」
- 「何度も指摘していることを自動チェックにして」

```text
/rule-lint
```

## 動作

- 規約を集める。出典の指定がなければ`CLAUDE.md`、`AGENTS.md`、`.mjun/steering/`、ADR、READMEの規約節を読む。レビュー指摘からは2回以上出た指摘だけを対象にする。
- 規約ごとに「完全」「部分」「不可」を判定する。
- チェック手段は、既存linterのルール、ast-grepルール、scriptの順で選ぶ。
- 各チェックに、直し方を含むメッセージとテストを付ける。例外は設定ファイルのファイル単位の除外に理由付きで書き、inlineの抑制コメントは使わない。
- チェックをgit hookとCIの両方へ接続する。agentのhookがリポジトリにあれば、そこにも追加する。
- 既存コードに違反があれば、「直す」「baselineに記録する」「警告から始める」のどれにするかをユーザーに選んでもらう。
- 規約文書を判定に合わせて更新する。「部分」の規約は文章を残し、チェックが拾わない範囲を書き添える。ADRは本文を書き換えず削除もせず、チェックの場所を示す `Enforced by:` の行だけを足す。チェックが置き換えるのは文章の規約で、判断の理由と履歴ではないためである。新しい規約が必要になった場合は、文書に書かずに提案する。

## 依存

- 対象リポジトリの言語に応じたlinter(ruff、eslintなど)
- [ast-grep](https://ast-grep.github.io/)
