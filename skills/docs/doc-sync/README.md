# doc-sync

[日本語](README_ja.md)

Compare documentation in the repository with the actual implementation, find the parts that are factually out of date, and rewrite them. It covers Markdown files, docstrings and header comments, OpenAPI/Swagger specs, and example config files. Style and wording preferences are not treated as drift.

All detected drift is applied in one pass without asking for confirmation. With `--dry-run`, nothing is edited and only the drift and before/after previews are reported.

## Usage

- 「ドキュメントを更新」
- 「READMEが古いので直して」

```text
/doc-sync
/doc-sync --dry-run
/doc-sync docs/api/
/doc-sync README.md --dry-run
```

## Arguments

| Argument    | Effect                                                                             |
| ----------- | ---------------------------------------------------------------------------------- |
| `--dry-run` | Report the drift and before/after previews without editing any file.               |
| `<path>`    | Limit the scan to a directory or file. Defaults to the whole repository.           |
| `language`  | Language for the updated text. Defaults to the language the document already uses. |

## Behavior

- Finds target documents, checks each statement against the code (paths, names, signatures, CLI flags, config keys, versions), and lists the drift per file and section.
- Updates only what is factually wrong, with the smallest edit, keeping the existing language, heading levels, list and table form, and docstring style.
- Drift it cannot resolve with confidence is skipped and listed in the final report.
- Always excludes `node_modules/`, `.git/`, `dist/`, `build/`, `vendor/`, `.venv/`, and `.mjun/`. Specs, steering, and experiment plans under `.mjun/` are never rewritten.
- Never commits.
- For OpenAPI specs generated by tools such as zod-to-openapi, it avoids editing and notifies the user. In large repositories and monorepos, narrow the scan with `<path>`.
