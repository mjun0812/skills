# Stop AI Slop

AIで書いたAI臭のする日本語の文章を、人間にとって自然で読みやすい文章に書き直す。
目標は2つ。AI臭を消すことと、読みやすい文章にすること。両者が衝突したら読みやすさを優先する。

対象はAIで書いた日本語の文章全般(ブログ、エッセイ、体験記、メモ、技術文書)。人間らしさを演出として足すことはしない。ムラや言い淀みは、書き手が立場と具体を持って書けた結果として生まれる副産物として扱い、後から注入しない。

AI臭さの中心は、記号や絵文字ではなく「書き手の不在」として扱う。
自分が何を見て、何に引っかかって、どこまで言い切るのか。その核をAIに預けると臭う。
全角ダッシュや偏愛語は、表面に出てくる症状でしかない。

書き手の不在は、身体性の欠如として文章に出る。人間はその時その場所にいて、経験に基づいて言えることしか言えない。好き嫌いがあり、知っていることと知らないことがあり、他者との関係がある。採点軸の立場・主体性・具体性・リズムは、この身体性が文章に残っているかを見る。AIはどれも持たず、常にプロとして全部の問いに同じ密度で答える。

脱臭の目的は、AIと見破られないことではなく、読み手の時間を無駄にしないこと。だから重大と推奨の振り分けは「理解を妨げるか」で決める。
書く前と書いた後に以下を確認した上で修正案を検討する。

- 自分は何を「○○だ」と引き受けているか
- 誰かが反論できる具体的な主張があるか(「いや、Bだろう」と言える内容か)

## 手順

1. 後述のチェック観点とリファレンスを読み、「主体と立場→構造→文・段落→語彙・記号→可読性」の順に修正点を洗い出す。問題箇所は必ず原文を引用して特定する。
2. 修正点を元に、採点項目にしたがって各項目を0〜10点で採点する。
3. 結果を出力フォーマットにしたがってユーザーに出力する。
4. ユーザーにどの修正点に取り組むかを番号で指定させる。
5. 指定された修正点だけを適用する。指定されていない箇所は変更しない。

### 修正案の制約

- 修正案が新しい事実(行為者、数値、固有名詞、エピソード)を必要とするときは、推測で補わない。「要確認: この方針は誰が決めたか」のように、書き手への質問の形で出す。行為者が分からないときは、複数の記録から観測できる変化として書き直す案を出す([structures.md 1-1](stop-ai-slop-jp-structures.md#1-1-主体のぼかし行為者の消去取り違え))。
- 具体が書けないのは、書き手がその話を持っていないから。校正側が具体例を作って埋めない。

### 採点項目

すべて「高いほど良い」で採点する。
目安: 0〜3=全面的な書き直しが必要、4〜6=問題が複数残る、7〜8=軽微な修正のみ、9〜10=そのまま出せる。

| 軸     | 質問                                                            |
| ------ | --------------------------------------------------------------- |
| 立場   | 反証可能な具体的主張があるか? 結論を回避していないか?           |
| 主体性 | 誰・何が何をしたかが見えるか?                                   |
| 具体性 | 抽象語で終わらず、固有の話や具体的な状況を書いているか?         |
| リズム | 段落の長さ・着地・文末の均一さが、内容の空疎さを隠していないか? |
| 簡潔さ | 冗長な前置き・重複・保険文がないか?                             |
| 可読性 | 一文が長すぎず、係り受けや指示語が迷いなく追えるか?             |

修正の要否は次で判定する: 重大な修正点が1件以上ある、またはいずれかの軸が6点以下なら「必要」。それ以外は「不必要」。

### 重大と推奨の振り分け

第一基準は「読み手の理解を妨げるか」。レベル(構造か語彙か)や修正の手間ではない。

- 重大: 理解を妨げるもの。主体と立場・構造レベルの問題、単独の否定文や免責の多発、読み手の反応を先取りするラベル付け、指示語や見出しで対象を追えない可読性の問題。
- 推奨: 臭うが理解は妨げないもの。語彙・記号レベルの問題、執筆態度のメタ宣言、冒頭の免責や情報の薄いまとめ節のような構造的な蛇足。読み飛ばせるので優先度は低い。

### 出力フォーマット

番号は重大→推奨の通し番号にする。問題箇所には原文の引用を入れる。

```markdown
## 判定

- 総評: ...(200文字以下。AI臭と読みやすさの両面に触れる)
- 修正: 必要/不必要

## スコア

| 軸     | スコア |
| ------ | ------ |
| 立場   | 0-10   |
| 主体性 | 0-10   |
| 具体性 | 0-10   |
| リズム | 0-10   |
| 簡潔さ | 0-10   |
| 可読性 | 0-10   |
| 合計   | 0-60   |

## 重大な修正点

1. 問題箇所: (原文の引用)
   問題: ...
   修正案: ...
2. 問題箇所: (原文の引用)
   問題: ...
   修正案: ...

## 推奨する修正点

3. 問題箇所: (原文の引用)
   修正案: ...
4. 問題箇所: (原文の引用)
   修正案: ...
```

## チェック観点

判定基準・実例・禁止リストの本体はリファレンス2ファイルにある。ここには各レベルで見る要点だけを置く。

### 主体と立場

参照: [structures.md 系統1](stop-ai-slop-jp-structures.md#1-主体を消す)、[系統5](stop-ai-slop-jp-structures.md#5-立場から逃げる)、[系統6](stop-ai-slop-jp-structures.md#6-無害さにチューニングされている)

- 反証可能な具体的主張を持つ。「重要だ」「本質的だ」で終わらせない。
- 確信度を偽らない。書き手が直接知らない事実を断定形で書かず、伝聞(「らしい」「ようだ」)のままにする。
- 「人々は」「多くのエンジニアが」「現代社会において」と遠くから語らず、具体的な人・失敗・数値・固有名詞を出す。
- 「ケースバイケース」で結論を回避しない。「○○もあり、△△もあります」の全方位肯定で判断を放棄しない。
- 曖昧さは出どころで判定する。確信度や対人関係から来る「思う」「気がする」「かもしれない」「知らんけど」は残す。免責から来る「あくまで個人の見解」「環境によって異なる」は消す。回数の上限は補助の目安。
- 表現が本来属する文脈と、この文章の主体の大きさが釣り合っているか見る。「文化が醸成される」は会社の公式サイト(主体=弊社)では自然で、個人の体験記に持ち込むと臭う。
- 「分からない」「調べていない」で終わる箇所を修正で消さない。すべての問いに同じ密度で答え切っている文章は、AI臭の兆候として見る。

### 構造

参照: [structures.md 系統2](stop-ai-slop-jp-structures.md#2-ドラマを偽造する)、[系統3](stop-ai-slop-jp-structures.md#3-英語ブログの骨格を直輸入する)、[系統4](stop-ai-slop-jp-structures.md#4-リズムを均す)

- 命題型H2を避ける。見出しは「テーマの名前」(名詞句)で作り、対象を含める。「分かったこと」「既知の弱点」のように対象を示さない見出しも避ける。
- 二項対比「AではなくBだ」・否定的列挙・劇的な断片化は、直接「Bだ」と書く。
- 単独の「〜ではない」「〜とは限らない」「〜を意味しない」が段落ごとに残っていたら、削除・肯定文化・補足として残す・段落の再設計のどれかで処理する。
- 「3つのポイント」「3つの原則」は、2つか1つに削れないか疑う。
- 序文の決めつけ→反転、体験→引用→抽象化のテンプレ反復をやめる。
- 段落の長さ・着地・文末の均一さ、箇条書きの項目の長さ・文法構造・粒度の揃いすぎは、AI臭の兆候として検出する。ムラを演出で足さず、原因(全段落への教訓の付けすぎ、同じ構造の文の連続)を直す。

### 文・段落

参照: [structures.md 1-2](stop-ai-slop-jp-structures.md#1-2-体験の壮大化)、[1-3](stop-ai-slop-jp-structures.md#1-3-一人称の消失と一般論)、[3-3](stop-ai-slop-jp-structures.md#3-3-一文圧縮wikipedia調)

- 自分の話を「多くの人」「我々」に一般化しない。
- 個人の体験を「真理」「境地」「美学」のような大きな話に膨らませない。
- 事実を一文に詰めすぎない。

### 語彙・記号

参照: [phrases.md](stop-ai-slop-jp-phrases.md)

- 偏愛語(泥臭さ、手触り、解像度、本質、営み、文脈、言語化)・必殺技造語(真理、虚飾、禁欲的、境地)を1記事に複数撒かない。
- 未定義の造語(「意思決定OS」「議論の通貨」)を既存の概念のように書かない。定義するか、普通の語に戻す。
- 横文字メタファー(思考のOS、ハック、インストール)・濫用されがちなビジネス用語・普通の日本語に戻せるカタカナを、日本語に戻す。
- 万能語(軸、置く、動く、崩れる、余白、面、強い/弱い)が具体的な操作や専門用語を曖昧にしていたら、元の語に戻す。
- 読み手の反応を先取りするラベル(「重要なのは」「面白いのはここです」「この三つを押さえれば〜が分かる」)と、執筆態度のメタ宣言(「ここは密度を上げる」)を消す。
- 根拠なし副詞(非常に、めっちゃ、普通に)は1段落に2個まで。「○○すぎる」は1記事に2〜3回まで。
- アカデミック自称(「本稿」「筆者」)を地の文で使わない。
- 全角ダッシュ「──」、形容詞・心情への「」、中黒「・」での3項目並列、Markdown外の`**`、段落末の装飾絵文字、タイトル・見出しの読点を消す。

### 可読性

AI臭とは独立に、読みやすさそのものを確認する。

- 一文が長すぎないか。読点が3つを超えたら分割を検討する。
- 修飾句の入れ子で係り受けが追いにくくなっていないか。
- 「それ」「この」「この結果」「両者」が何を指すか一意に決まるか。話題が変わるときは指示語だけで接続せず、対象を名詞で言い直す。
- 段落の先頭の文だけを拾って、話の流れが追えるか。「同様に」「効果」「この結果」のように複数の対象を指し得る語で段落を始めていないか。
- 表・箇条書きの前に、列挙する対象と分類基準が書かれているか。「次の3つ」と個数を宣言したら、項目数と一致しているか。
- AI臭の修正が読みやすさを壊すなら、読みやすさを優先する。
