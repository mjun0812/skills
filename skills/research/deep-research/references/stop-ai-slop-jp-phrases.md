# 撲滅すべきフレーズと語彙

語彙レベルのAI臭。どの語も1〜2回なら自然で、1記事に頻出すると臭う。全部消す必要はない。

## 1. 定型句と偏愛語

### 表層の定型句

- 「いかがでしたでしょうか」「いかがでしたか」
- 「ぜひ参考にしてください」「ぜひ〜してみてください」
- 「○○の重要性を再認識しました」
- 「近年〜が注目されています」
- 「現代社会において〜は重要なテーマです」
- 「○○することが大切です」「○○することが重要です」
- 「○○に他なりません」
- 「ご質問ありがとうございます」(質問への丁寧な復唱)

### AI偏愛語

具体性を装った抽象語。

**質感を装う語**

- 泥臭い、泥臭さ
- 手触り
- 肌感、肌感覚
- 体温、温度感
- 熱量
- 血の通った

**認知を装う語**

- 解像度(「解像度が上がる」「解像度が高い」)
- 腹落ち
- メンタルモデル
- 文脈(やたら言いたがる)
- 言語化(「その言語化は本質を突いている」)
- 落とし込む(「〜に落とし込む」)
- 一段(「一段上がる」「一段深い」)
- フェーズ(「削るフェーズ」)

**評価を装う語**

- 本質、本質的
- 地に足のついた
- 等身大

**抽象比喩**

- 営み(「○○という営み」)
- 装置(「○○装置」)
- 設計(体験や状況に対して「設計されている」と書くクセ)
- インフラ(物理的なインフラではない用法)
- 接続(「人の接続」のような抽象用法)

**思想語**

- 思想(「○○の思想」)
- 原則(「3つの原則」)
- 哲学(「○○の哲学」)

### 必殺技造語(壮大化のための漢字熟語)

普通の感想を、必殺技みたいな漢字熟語で大きな話に仕立てるための語。
1〜2個ならカッコつけで済むが、複数並ぶと一気にAIクサくなる。

- 真理、真実
- 結末、宿命、運命
- 境地、極致、究極
- 虚飾、装飾、虚像
- 美学、徳、品性
- 重厚感、深淵
- 禁欲的、優美、優雅、繊細
- 残酷、冷徹、冷酷、過酷
- 凝縮、結晶、結実

「枯淡の境地」「冷徹な結末」「残酷な真理」「虚飾を剥ぎ取る」「禁欲的な美学」「重厚感の欠如」のように複合的に使われると一発でAI臭になる。
普通の感想なら普通の語彙で書く。

### 未定義の造語

既存の概念であるかのような専門用語を、その場で作るクセ。「意思決定OS」「概念辞書」「議論の通貨」「supervision paradox」。定義がないまま、以後の文章がその語を前提に進む。必殺技造語が壮大化のための語なのに対して、こちらは専門家っぽさの偽装。

判定: その語に定着した用法があるか。なければ、定義を書くか普通の語に戻す。「意思決定OS」→「意思決定の手順」。

### 比喩のテンプレ語

これらの比喩を同じ文章で3回以上使ったらAI臭。

- 地図、羅針盤、コンパス
- 仕様書、設計書、レシピ
- 土台、柱、骨格
- 栄養、エンジン、潤滑油、スパイス
- DNA、車の両輪
- 触媒、起爆剤

## 2. 翻訳調

### 翻訳調動詞

主体を抽象化した分析動詞。英語の point to / suggest / emerge などの直訳。

- 指している(「同じ方向を指している」)
- 示している、示唆している
- 物語っている
- 浮かび上がる、見えてくる
- 対比をなしている
- 収斂する
- 整理する、考察する
- 捉える、論じる、位置づける

## 3. 英語ネイティブ思考の漏れ

LLMが英語で大量に学習している副作用。日本語に直訳した結果として残るカタカナ・固有名詞のクセ。

### 横文字メタファー(IT/システム用語の比喩使用)

IT・SE用語を、本来関係ない場面に比喩で持ち込むクセ。普通の日本語に置き換えできるところを、わざわざシステム用語で書いて先進的っぽい雰囲気を出す。

| 避ける                           | 使う                     |
| -------------------------------- | ------------------------ |
| 思考のOSをアップデートする       | 考え方を変える           |
| 人生をハックする                 | 工夫する、コツを掴む     |
| 新しい習慣をインストールする     | 習慣をつける             |
| マインドをリファクタリングする   | 考え方を整理する         |
| 頭の中にラボを持つ               | 頭の中で試す             |
| キャリアをポートフォリオで考える | 仕事の組み合わせで考える |
| 学びをアセットにする             | 学びを積み上げる         |

コンサル・スタートアップ界隈の語彙を AI が大量に学習している副作用。放っておくとこの手の比喩を撒いてくる。

### 過剰なカタカナ表記

普通の日本語に戻せるカタカナ語を、わざわざカタカナのまま書くクセ。

| 避ける                 | 使う             |
| ---------------------- | ---------------- |
| コンテキスト           | 文脈、状況       |
| アライメント           | 揃える、合わせる |
| コミュニケーション     | 話す、伝える     |
| インテグリティ         | 誠実さ、一貫性   |
| コラボレーション       | 共同作業、連携   |
| インプリメンテーション | 実装             |
| プライオリティ         | 優先             |
| アグリー               | 同意、賛成       |
| ナレッジ               | 知識、ノウハウ   |

カタカナを完全に排除する必要はない(技術用語は技術用語のまま)。
普通の日本語で言えるところまでカタカナにしているとAI臭になる。

## 4. 立場を薄める語

### 結論回避フレーズ(事なかれ主義)

すべての立場を紹介してどれも選ばない、AIのデフォルト挙動。

- 「ケースバイケース」
- 「場合によります」
- 「価値観によります」
- 「状況に応じて異なります」
- 「一概には言えませんが」
- 「一般的には」
- 「メリットもあればデメリットもあります」
- 「○○という側面もありますが、一方で〜」
- 「賛否が分かれるテーマです」

### 三段ヘッジ

同じ段落で複数のヘッジを重ねるとAI臭になる。1段落に1つまで。確信度から来る「思う」「気がする」「かもしれない」は数に入れない(structures.md 5-2)。数えるのは免責のためのヘッジ。

- 「○○ことがある」
- 「○○場合がある」
- 「○○可能性がある」
- 「○○なりうる」
- 「○○とは限らない」
- 「○○と言えなくもない」
- 「あくまで○○として捉えるのが正確だ」

### 曖昧な断言(vague declaratives)

「重要だ」「深い」「構造的だ」と言うが、具体的に何が・どう・なぜ、を書かない。

- 「本質的な問題がある」
- 「構造的な課題である」
- 「示唆に富む結果だ」
- 「重大な意味を持つ」
- 「根本的な転換が必要だ」
- 「深い洞察が得られる」
- 「重要な示唆を含む」

修正方針: 具体的な「何が」「なぜ」を書く。書けないなら、その文を削る。

### 弱い否定

はっきり「やるな」と言うべき場面で弱めるクセ。

- 「あまり推奨されません」
- 「注意が必要です」
- 「望ましくないとされています」
- 「避けたほうが良いでしょう」

修正方針: 「やるな」「ダメだ」と言い切る。

### 強い評価+根拠なし

ホメるときは具体的な根拠を添える。根拠なしの大言は逆に薄い。

- 「非常に有効です」
- 「画期的な手法です」
- 「革新的なアプローチです」
- 「大きなメリットがあります」
- 「驚くべき効果が期待できます」

## 5. 読み手の反応の先取りと自己解説

### 読み手の反応の先取り(self-labeling)

本題に入る前に、読み手にどう感じてほしいかを指定するフレーズ。内容とは無関係に「ここは重要」「ここは面白い」とラベルを貼る。読み手が自分で得るはずの効果を先回りして指定するので、時間稼ぎであるだけでなく理解の妨げになる。削除して直接本題に入る。

前置型:

- 「重要なのは」「ここで重要なのは」
- 「面白いのは」「興味深いことに」
- 「結論から言うと」(言いつつ結論が薄い場合)
- 「正直に言うと」「率直に言いますが」
- 「避けたいのは」
- 「まず前提として」
- 「実はですね、」
- 「ひとつ言っておきたいのは」
- 「結局のところ」「本当のところ」
- 「あえて言うなら」

後置型:

- 「面白いのはここです」
- 「ここがポイントです」
- 「これが本質です」

読了効果の指定:

- 「この三つを揃えると〜が判断できる」
- 「ここを押さえれば〜が分かる」
- 「これで〜の解像度が上がる」

### メタコメント(自分の文章を解説するクセ)

構造を本文で予告するパターン。

- 「それぞれ順に見ていきましょう」
- 「ここからが本題です」
- 「補足ですが、」
- 「ステップ1」「STEP1」「Step1」
- 「○○について、改めて整理します」

執筆態度を宣言するパターン。読み手には無関係。

- 「ここは密度を上げる」
- 「主張の範囲を丁寧に切る」
- 「以下は慎重に書く」
- 「あえて断定的に書くと」

## 6. 強度の振り切り

全部を強い言葉で塗らない。

### 根拠なし副詞

英語の "really" "just" "literally" 系の翻訳。1段落に2個以上重なったらNG。

- 非常に、とても、かなり
- めっちゃ、ガチで、マジで
- 普通に(意味のない強調用法)
- 本当に、実に
- 確かに(意味のない同意)

### 「○○すぎる」連発

ポジティブ体験の強度を一律に振り切るクセ。1記事に2〜3回まで。

- 「美味しすぎ」「気持ちよすぎ」「優雅すぎ」「感動的すぎ」「ヤバすぎ」

全部に貼らない。中間温度(「悪くない」「まあまあ」「微妙」)を混ぜる。

### 「(笑)」の文末貼り付け

絵文字的に文末へ律儀に付けるクセ。1記事に1〜2回まで。

## 7. ビジネス用語の濫用

普通の日本語に置き換える。`3. 英語ネイティブ思考の漏れ` の横文字メタファーと並走して撒かれることが多い。

| 避ける                   | 使う                         |
| ------------------------ | ---------------------------- |
| 〜にコミットする         | 〜をやる、〜を引き受ける     |
| 〜にレバレッジを効かせる | 〜を活用する                 |
| 〜の解像度を上げる       | 〜を詳しく知る、〜を理解する |
| 〜にディープダイブする   | 〜を深く見る、〜を調べる     |
| 〜をアラインする         | 〜を揃える、〜を合わせる     |
| 〜のスケールを取りに行く | 〜を広げる                   |
| ROIを最大化する          | 効率を上げる                 |
| 〜にピボットする         | 〜に方針転換する             |

### 飾りの段階名

計画文書で、段階の名前にプロダクト開発用語を飾りとして使うクセ。本来の意味(MVP=ユーザーに出せる最小の製品、PoC=概念実証)から外れた「小さく試す」程度の用法なら、日本語に戻す。「動作確認 MVP」のように日本語の言い換えを併記しないと通じない時点で、その語は情報を足していない。

| 避ける             | 使う             |
| ------------------ | ---------------- |
| 動作確認 MVP       | 動作確認         |
| 評価 MVP           | 小規模試行       |
| PoC を回す         | 試作して確かめる |
| パイロット版で検証 | まず小さく試す   |

判定基準: その省略語に固有の意味が乗っているか。日本語に置き換えて情報が落ちないなら戻す。smoke test(本実行前にパイプラインが通るかだけ確認する走行)のように、確立した技術用語をその意味どおりに使っている場合は残す。

## 8. 機械処理の残骸

出力処理や貼り付けの痕跡として残る記号やフレーズ。原因は機械処理側にあるので、検索 → 全置換で機械的に潰せる。

### 強調の `**` 残骸

AIが Markdown で出力した強調記号が、消し忘れで残るパターン。

```
**SEO対策をするためには**以下のような施策が効果的です。**
```

### 全角文字に紛れた半角スペース

```
SEO対策をする ためには以下の ような施策が効果的です。
```

半角スペースを検索して、不要なものを削除。

### 全角ダッシュ ──

英語の em-dash の直輸入。日本語ではコロン、改行、読点に置き換える。本文に混入していないか検索する。

### チャット応答の残骸

チャットの返答をそのまま文書に貼ったときに残る、対話の続きを前提としたフレーズ。文書には対話相手がいないので削除する。

- 「必要なら次に、〜まで落とし込みます」
- 「〜を知りたいですか?」「〜も出せます」
- 「その言語化は本質を突いています」「良いところまで来ています」(相手の入力への評価)
- 「ここからは「削る」フェーズです」

## 9. 万能語と平易化の換喩

正確な操作や専門用語を、何にでも使える曖昧な語に置き換えるクセ。横文字メタファー(3)の逆で、専門的な内容を平易に見せようとして、かえって何を言っているか分からなくなる。技術文書で特に多い。

### 万能語

- 軸(「評価の軸」「この軸で見ると」)
- 置く(「シナリオを置く」「テストを置く」)
- 動く(「評価が動く」「最適点が動く」)
- 崩れる(「前提が崩れる」)
- 余白(「解釈の余白」)
- 面(「技術面」「運用面」の濫用)
- 強い/弱い(「この構成は運用に強い」)
- 接続(「〜への接続」)

判定: その語を具体的な操作や専門用語に置き換えて情報が増えるなら戻す。比喩を残せるのは、その語が分野で定着している場合か、直後に技術的な意味を定義する場合だけ。

| 避ける                 | 使う                                                     |
| ---------------------- | -------------------------------------------------------- |
| 「軸」(比較の観点)     | 比較基準、比較項目                                       |
| 「軸」(測る内容)       | 評価方法、評価指標、測定対象                             |
| 「軸」(複数の性質)     | 性能要素、変数                                           |
| 計画シナリオを置く     | 仮定する                                                 |
| テストを置く           | 用意する、実施する                                       |
| 評価の単位が動く       | 主要な報告値に○○が加わった                               |
| 予算をモデル規模へ配る | 固定計算量のもとで、パラメータ数と訓練トークン数を決める |
| 前提が崩れる           | ○○という条件が成り立たなくなる                           |
| 運用に強い             | ○○の障害時に手動介入なしで復旧する                       |

「軸」はグラフの横軸・縦軸、回転軸のようにaxisを指すときだけ使う。「置く」は物理的・数学的な位置を表す用法だけ残し、掲載・説明・仮定・定義・作成をまとめている用法は、操作を表す動詞に変える。
