# Skill Distribution Tool Comparison

A comparison of the five distribution channels this repository supports (Claude Code plugin / Codex plugin / npx skills / gh skill / apm). Researched on 2026-08-28.

Broadly, the two plugin systems (Claude Code / Codex) follow a "subscription" model (register the repo as a marketplace, install the plugin as a whole, and updates arrive automatically), while the three CLIs (npx skills / gh skill / apm) follow a "copy" model (pass the owner/repo name directly and copy files locally). This difference in design philosophy drives most of the rows below.

## Notes

- Only the Claude Code plugin and apm can distribute agents. The three reviewer agents in this repo ([agents/](../agents/)) rely on exactly that; on other install methods the github-pr-review skill falls back to generic subagents. apm's `-t codex` conversion works, but it drops the `tools` restriction from the frontmatter, so converted agents inherit all tools.
- Codex also reads `.claude-plugin/marketplace.json` as a legacy-compatible marketplace (confirmed in the source code). Claude-specific variable expansion such as `${CLAUDE_PLUGIN_ROOT}` is incompatible, though, and there are reports of broken MCP configs ([openai/codex#19372](https://github.com/openai/codex/issues/19372)). Codex also has a separate `$skill-installer <skill-name>` mechanism that adds a single skill without installing the whole plugin.
- Cleanup of removed skills: the two plugin channels and apm remove them automatically on update, while npx skills / gh skill leave local copies behind that must be deleted manually (this is the basis for the "Removed skills" table in the README).
- The npx skills lockfile is close to write-only: an `npm ci`-style full restore from the lockfile is unimplemented ([vercel-labs/skills#549](https://github.com/vercel-labs/skills/issues/549)). If reproducibility matters, apm's `apm.yml` + `apm.lock.yaml` is currently the only manifest-driven option.
- gh skill has no uninstall command ([cli/cli#13706](https://github.com/cli/cli/issues/13706)). Instead of a lockfile, it stamps provenance metadata such as `github-repo` / `github-ref` into the SKILL.md frontmatter at install time.
